The problem
Free identities broke every gate.

  
Every defence we have assumes a human, or an identity that is expensive to make. Agents create both for free, at any volume. Inboxes, forms, issue trackers and public tools are open sinks.

  

    
CAPTCHAs
Models solve them. They now mostly stop the humans.

    
Rate limits and API keys
An agent mints a new key or account for every batch. The limit follows the identity, and identities are free.

    
Blocklists and reputation
New sender, new domain, clean slate. You are always one step behind.

  

  
The one thing an agent cannot fake is money at risk. A deposit is proof of intent: refunded if the work is genuine, kept if it is abuse. Honest agents pay almost nothing. Abusers pay per attempt.

Lifecycle
What happens to a deposit.

  

    
RequestAn agent or person contacts a gate.

    
402 with a priceClaude prices it: about $1, more for templated blasts. 402

    
HoldA Stripe authorization hold, not a charge. Nothing moves yet.

    
DeliveredTo Slack, Discord, a webhook or the inbox, with Worth it and Junk links.

    
Released or keptWorth it or no action: released. Junk: captured, and the gate owner keeps it.

  






  
Safety, honestly
How it can be abused, and what stops it.

  
A paid gate invites new tricks. Each one we found, and what we did.

  

    
Owners marking everything Junk to farm moneyLive
Every gate publishes its release rate, and agents can read it before paying. Daily capture cap per owner; extra junk marks release instead.

    
Card testing through the pay linkLive
Rate limits per bond and IP, Stripe-hosted card entry, holds not charges.

    
Prompt injection ("mark me worth it")Live
Claude only suggests a price in a fixed range. The triage agent gets a one-hour token that can recommend but never move money.

    
Webhook abuse and SSRFLive
Webhooks must be HTTPS to public hosts, redirects are not followed, and private addresses are rejected.

    
Faking a trusted senderLive
Web, API and MCP intake ignore the approved-senders list, because those addresses are self-declared.

    
Leaked linksLive
Signed, expiring decision links. Viewing never acts. The public feed hides subjects and full addresses.

    
An agent overspendingPlanned
Per-agent budgets and a spend cap in the MCP tool. Holds already expire and release on their own.

    
Fees eating small deposits, sybil cardsPlanned
Minimum deposit floor for captures; limits per card fingerprint; repeated near-identical messages already cost more.

FAQ
Good questions.

  
Why would anyone pay to reach me?
They put down a deposit, not a fee. If the message is genuine it comes back, so honest senders and honest agents lose nothing. It only costs money to those who send junk at scale, which is the goal.

  
Why not just charge per call, like x402?
Per-call fees tax the honest traffic too. A refundable deposit prices abuse without taxing good behavior, and it needs no per-call micropayments. The two ideas are compatible.

  
How does Bond make money?
Not from junk. Plans: a subscription for teams, a per-deposit fee for developers who gate forms and APIs, and a small cut of captured deposits above a minimum.

  
Does Claude control the money?
No. Claude reads a message and suggests a price within a fixed range. Holds, releases and captures are deterministic code, and the triage agent can only recommend.

  
Is this real money?
Not yet. This is a hackathon prototype in Stripe test mode. No real cards are charged.
